## 角色与职责（最小集）

| 角色 | 职责 | 不做什么 |
|---|---|---|
| 制造商合规负责人 | 授出 mandate、签核文书 | 不改记录格式 |
| 主智能体 | 执行流程、产出证据、按 schema emit | 不自评 verdict（避免自查） |
| 见证服务 | 记授权授予与证据事件、签 attestation | 不下合规结论 |

| 第二方复跑者 | 只按公开约定重算 | 不读实现代码也能得到同结论 |

## 技术前提（缺一项就跑不通）

1. **文件控制可得**：`process_state.procedure/revision` 必须能从文档控制系统取，不能人工填。
2. **身份可绑**：`grantee.agent_id` 必须是企业目录里的一级身份（Entra Agent ID / Okta Agent SSO 这类），否则 R1 的"稳定身份"落空。
3. **授权有版本**：mandate 必须有可判定的版本与有效期，且吊销可查。
4. **证据可哈希**：证据以哈希入记录，原件仍在 QMS；不允许记录里出现路径或令牌（C7 就是拦这个）。
5. **状态变化可发现**：需要一条"受控程序变更"事件源，否则 C4 只能返回 no_state_reference。

## 已知缺口（不要对外说成已解决）

- **无真实制造商数据**：现在所有样例是合成的。P1 之前，任何"已在产线跑"的说法都是假的。
- **无独立第三方验证**：P3 未做。自跑只能证明可复现，不能证明独立。
- **无监管方背书**：P4 未做；不能暗示审核员已经接受这种记录。
- **无 conformance 认证**：没有认证机构参与，schema 只是提案。
